# 主动保存与检索提示词

实现是结合行为原则重新编写的提示词，不直接复制两家产品的大段原文。

## 语言

0.5.1 起，所有注入给模型的提示文本都是简体中文：`MEMORY_POLICY`、`EXTRACTION_POLICY`、6 个 `md_memory_*` 工具说明与参数说明、索引 footer、上下文里的「记忆不可用」提示。工具名、参数名、`scope`/`type` 取值、提取 JSON 的字段名保持 ASCII。仍然保持英文的模型可见文本：索引标题 `## Memory index (shown/total; partial|complete)`（`tests/retrieval.test.ts` 断言该格式）、`MemoryError` 的错误消息与错误码（`tests/host-harness.mjs` 有断言依赖）。

注意 esbuild 默认把非 ASCII 转义成 `\uXXXX`，所以 grep 构建产物里的中文要按转义序列找，或先解码再比对。

## 融合内容

| 来源 | 采用的行为 |
|---|---|
| ZCode | 稳定偏好、纠正、项目决策与引用四类；主动保存；创建前搜索查重；一条主题一个文件；默认项目作用域；无长期信息时返回空操作；成功轮后处理新增窗口。 |
| Claude Code | 记忆与当前指令分离；索引只是读取指针；保存偏好而非临时进度；追问历史决定时必须检索正文；易变事实必须重新验证；未提交前不声称已经记住。 |
| 本插件 | 统一使用 md_memory_* 工具；索引由存储层维护；更新带 revision/hash；短索引与正文使用独立预算；遗忘即时处理；后台提取没有工具权限。 |

主提示词在固定系统段注册，明确“应主动保存哪些信息”“哪些问题必须先检索”“用户要求记住必须当轮执行”。动态上下文只放条目目录和当次相关正文。

后台提示词单独定义：只判断新的真实对话窗口与候选清单，返回一个 JSON 对象，可合法返回空 operations。更新保留仍有效的事实并带当前修订/hash；不存在正文的候选只用于查重，更新交由主 Agent 读取后处理。

这些提示词提高主动写入和检索的概率；最终选择仍由模型完成。后台辅助调用补处理遗漏，不把主 Agent 任意一次写入当成整轮无需再分析的理由。

## 粒度：一条主题一条目（不是一条事实一条目）

0.5.1 之前，主提示词与后台提示词都以 `keep one durable fact per entry` 收尾，与本文档所称的 ZCode「一条主题一个文件」相反：一个主题天然由多个事实组成，于是同一对象被拆成多条平级条目（本机实测：Windows 控制 iPhone 一条主题散成 4 条，日志显示这 3 次写入前后 `md_memory_search` 调用为 0）。

现在的协议把粒度与归属判定写死：

- **条目拥有一个主题**（一条工作流、一台机器、一个组件或一条长期约束），事实是该条目内的段落；同一主题的第二条条目即使标题、标签、文件名都不同也是错的。
- **同一对象的新结论、细化或反证都是更新**，不是新条目：原地改写、保留仍有效的事实、给被改动的行标日期与改动原因；验证发现旧记忆过时必须在同一轮回写。
- **先查后建（新建是正常结果，只是不是默认动作）**：已有条目覆盖该主题（哪怕只是部分覆盖、或版本已旧）就更新它；没有任何条目覆盖才新建——新信息本来就该新建，不需要额外仪式。
- **找不到就新建**时给条目一个稳定 topic tag；同一对象的旧结论过时，必须在同一轮把它改掉，而不是另起一条。
- 写前必须走三步：至少两个角度 search（对象 + 结论）→ read 所有可能的宿主条目 → 有宿主就更新它（带 revision/hash），没有才新建。索引按相关性排序并可能在不同标题下给出同主题条目，**没 read 过的条目不算查过**。
- 索引 footer（`src/retrieval.ts` 的 `INDEX_FOOTER`）重复这条纪律，因为它每轮都出现在条目旁边，离写入决策点最近。

后台提示词同步收紧：任何候选拥有该主题就必须返回该条目的更新（即使标题不同）；宿主不在候选清单里时不得为该主题新建条目，返回空操作交给主 Agent。
